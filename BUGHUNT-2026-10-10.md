## Checked and clean
- Work lifecycle: 45,000 random steps (claims with/without leases, stale and held attempts, fail with/without retry, removals, re-joins, clock): at most one completion, done/failed exclusive, holders are current members, attempts never go down. Kept as `test/work-property.test.ts`.
- Permissions: 40,000 checks against an independent reference of "own capabilities cut down to the realm's": reads, posts, `targets`, `inbox`, `route-recent`. Kept as `test/permission-property.test.ts`.
- Stateful random HTTP calls (5 actors with tokens, ids harvested from earlier answers, removals/leaves/joins interleaved; 27,308 calls over 25 seeds, 27 operations reached): no 5xx, every answer JSON, and database invariants hold (one holder per claim and only a member holds, one completion per work, one resolution per decision and inside its options, valid finding and presence states, each submission routed once, answers only from members or the addressee and an invited expert only once). A shorter run is kept as `test/fuzz-http.test.ts`.
- Router and host loop under chaos (a classifier that returns garbage, NaN confidence, unoffered choices, throws plain/transient/per-message errors or is slow; random submissions, posts, work, removals and joins; shadow and enforce; a flaky worker): 894 submissions over 40 seeds, no submission with two verdicts or left pending after recovery, no double delivery, nothing delivered in shadow mode, no work completed twice, no unhandled rejection. A shorter run is kept as `test/fuzz-router-host.test.ts`. Note: the first run used a plain LCG whose first draw is nearly the same for small seeds, so shadow mode was never exercised; the property tests now use mulberry32 and still pass.
- Upgrade path: a database written before migration 12 (simulated by dropping `events.args_hash` and setting version 11) upgrades with all its events, keeps working, replays old events without a hash, and 12 processes opening it at the same time all succeed. Kept as `test/migration.test.ts`; the next migration should extend it.
- Mutation testing of Core's guards: every `this.mustMember`/`mustRouter`/`requireHolder` call replaced by a no-op (29 mutants) and every one-line `if (...) throw new Error(...)` disabled (64 mutants), each against the fast part of the suite (about 4 s per mutant). 10 + 14 mutants survived at first, i.e. checks whose removal no test noticed: `test/authorization-matrix.test.ts` and `test/guards.test.ts` now kill all of them (`ops.ts` 7, `router.ts` 5, `jev.ts` 3, `host.ts` 3, `memory.ts` 4 and `pi.ts` 7 further guards were mutated too: only two survived, FIND without a memory and FIND without words, now in `test/pi-find.test.ts`) except four defensive guards that cannot be reached inside a transaction (`changes !== 1` in claim, complete and fail) or give the same refusal through a second check (`removeMember` of an unknown context).
- Worker and launcher: error classification matches Core's real messages (`already done/claimed/failed`); the Job manifest cannot be overridden by profile `env` (the `PIO_*` entries come last); ids in annotations are bounded by the new size limits.
- Tools sandbox (`read_file`, `list_dir`): `../`, absolute paths, symlinks to files and directories (absolute and relative), NUL bytes, a `root` smuggled in the arguments, wrong argument types: nothing escaped and nothing leaked. Only observation: `list_dir` marks a symlink to an outside directory with a trailing `/` (its type, not its content; symlinks can only be made by the operator).
- HTTP: auth (missing, bad, revoked, expired, lowercase scheme, token in query, Basic), routes, methods, body limits, malformed bodies, identity in the body ignored.
- Fuzzing every parameter of every op with 20 hostile values, as three different actors: no 500-class error left.

## The four open items, with the opinion of the other session (piople master owner, 2026-10-10) and what was done
1. **Replay with a different payload is silent.** Opinion: tighten only for keys the caller supplied (`key-conflict` when the same user key comes with different content); keys derived by default may stay permissive, since their idempotency is deliberate (for example `decide` on an already resolved decision). **Done** on `fix/key-conflict` (migration 12 adds `events.args_hash`; set only when the caller chose the key; host-derived keys are marked `derived-key` and stay permissive; events from before the migration carry no hash).
2. **No size limits in Core.** Opinion: yes, generous, per field. **Done** (`ARG_LIMITS` in `ops.ts`): 1,000,000 characters per argument by default, 2,000 for a title, 500 for a name, 200 for ids, skills and keys, 20,000 for goal, question, reason and answer; JSON values are measured serialised; the error is `too-large` (HTTP 413). Test in `hardening.test.ts`.
3. **Work addressed to a non-member.** Opinion: leave it allowed (the Temporal orchestrator and the k8s launcher address a named actor that may register later); show it as "not takeable". **Not changed.**
4. **`decide` answers must be options.** Opinion: strict is right; free text only through a deliberately chosen option list. **Kept.** (Their decision gate uses `allow,deny`, the defaults are `yes,no`.)
